# pixi-release documentation

This site will document the `pixi release` lifecycle:

1. Inspect and record an immutable release plan.
2. Prepare reviewed release changes without publication.
3. Cut and tag only after preconditions pass.
4. Verify source and artifacts against recorded evidence.
5. Publish targets independently and resume safely.

The source of normative project decisions is Backlog.md. This public site describes supported behavior once it exists.
